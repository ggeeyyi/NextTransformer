本页跟踪 [Arena v2](../overview/) 与研究 gym（`nextt_gym/`）背后的工作：已经交付了什么、还剩什么、按什么顺序推进、还有哪些决定待做。
它报告的是工作状态，而不是研究结果；约束参赛作品的是[竞技场规则](../rules/)。更新于 **2026-11-02**。

| 状态 | 含义 |
|---|---|
| **完成** | 所述交付物已经存在，并有所列证据。代码、有界检查和已发布的结果是彼此独立的声明。 |
| **部分完成** | 已有部分交付物；剩余工作已写明。 |
| **待开始** | 计划中的工作或决定，尚无完成证据。 |
| **推迟** | 保留其触发条件；不代表现在就要投入算力。 |

## 路线图与本计划的对应

| Arena v2 的[路线图](../../roadmap/)条目 | 本页中的工作 |
|---|---|
| 带 MCP 工具的研究 gym，在 dev 划分上打分，验证集和 CORE 保持封存 | A1、AR-01、G1、G2 |
| 每次尝试都有计量的算力和研究轨迹 | G4（AR-07） |
| 自我改进的研究循环 | A5 |
| 按研究者排名的排行榜 | G4：先做描述性展示，有了可比较的研究过程后再定排名规则 |

无人值守的 agent，以及随之而来的第一个完全由 agent 完成的（L0）参赛作品，要等隔离工作 G3 完成。

## 竞技场工作

| 编号 | 状态 | 已交付 | 剩余工作 |
|---|---|---|---|
| A0 — 初版竞技场 | **部分完成** | 规则、任务、披露卡片的格式、模板和检查器，pull request 范围检查，竞技场页面，来源徽章和筛选，以及 [Circle Loop](../circle-loop/) 示例（历史示例，L3） | 团队审阅并定稿规则和任务文本 |
| A1 — 研究工具 | **部分完成** | 研究 gym：四种规模上的 dev 划分打分（S 和 C 为 512 次更新，M 为前 2,000 次，L 为正式调度），FLOPs 账本，归档，以及通过 MCP、HTTP 和 Python 提供的 22 个操作；dev shard 的 SHA-256 已固定 | 由 gym 尝试生成披露卡片（G1）；AR-01 的剩余部分 |
| A2 — 代理指标的可信度 | **部分完成**（AR-03） | Arena v1 Stage 1：512 次更新的运行可以筛掉候选，但不能给候选排名；排名需要 2,000 次更新的前缀（M）。Stage 2：在 M 规模上做了三轮候选搜索 | 发布 Stage 1–2 的证据；在继续投入之前，决定是否以及如何推进最好的候选（Stage 3）；报告小样本的局限 |
| A3 — 第一个 L0 参赛作品 | **待开始** | agent 任务说明 | 无人值守运行之前先完成 AR-01 和 G3；确定完整运行的预算；然后在没有人类研究输入的情况下走完准入和结果流程 |
| A4 — 公开开放 | **部分完成**（AR-06） | 仓库自 2026-10-31 起开源；文档和观测站发布在 GitHub Pages；pull request 模板带有披露条目 | 决定检查点和产物的托管方式 |
| A5 — 参考脚手架 | **推迟** | 供外层循环使用的 gym 接口 | 一个最小、可复现的 agent 循环，用于在脚手架固定的条件下做比较 |
| A6 — 验证升级 | **推迟；按触发条件** | 基于信任的规则、源码和数据身份、已发布的证据 | 前缀重放、种子噪声估计或私有的留出集，只在提交规模、相互矛盾的声明或接近的差距需要时才做 |
| G1 — 从 gym 尝试到参赛作品 | **待开始** | 尝试、归档和计量的研究历史 | 把一个尝试变成准入 pull request 所需的插件、配置、成本证明和披露卡片 |
| G2 — 统一训练路径 | **待开始**（AR-02） | gym 和正式训练各有一个训练器 | G2a：初始化、数据、损失、优化器和续训一致。G2b：哈希冻结的候选通过正式训练器，具备完整评测、算力核算、来源记录和导出资格。在 G2b 和评分规则决定之前，gym 的 L 运行只用于研究 |
| G3 / P6 — 隔离 | **部分完成；待集成**（AR-04、AR-05） | gym 中的静态检查和 API 封存；候选运行时和评分工具，尚未进入本仓库 | 在一条受支持的硬件和启动路径上，证明训练读不到保留数据、也改不了评分；冻结模型交接并独立评分；测试训练、更新和续训，也测试被禁止的路径。无人值守的 agent 之前必须完成 |
| G4 — 计量赛道 | **待开始；先做披露**（AR-07） | 服务端 FLOPs 账本；每次运行训练和评测的 GPU 小时 | 计量来源、账本快照、失败和验证中的尝试、平台 GPU 小时（集群运行目前只报告训练和评测时间，不含准备和排队）、墙钟时间，以及 LLM token 和 API 费用；未知值保持为空 |

## gym 状态

| 交付物 | 状态 | 证据与边界 |
|---|---|---|
| 研究服务、验证和核算 | **实现完成** | 通过 MCP（stdio、Streamable HTTP）和 Python 提供的 22 个操作，阻塞式评测适配器，候选验证和校准，带事件和幂等的持久存储，预算的预留、扣费和结算，以及归档。见 gym 的 README 和 `INTERFACE.md` |
| 与竞技场对齐及 CI | **完成** | S 是研究运行，不是协议 pilot；dev 划分；gym 运行和导入运行的官方结果都封存；L 使用协议种子；参赛作品不得修改 gym；CI 运行 gym 的测试套件 |
| 接口一致性 | **完成** | 测试对照 `INTERFACE.md` 检查对外提供的工具、资源、prompt、事件类型和任务卡片；集群后端的测试只接受其 CLI 认可的命令行 |
| agent 与 GPU 冒烟测试 | **在冒烟范围内完成** | 合成 token 的数据并行 BF16 更新及账本结算，以及通过 MCP 的 agent 迭代（包括父到子）；不是真实数据的实验 |
| 集群上的真实数据 | **部分完成；AR-01 已做有界验证** | 使用真实分词器和数据的 S 运行，从检查点的分段续训和意外中断后续训，预算结算，包括导入运行在内的封存，以及跨会话恢复。剩余：从归档生成披露草稿，然后验收选定的生产路径。更多后端不在第一个版本之内 |
| 正式结果资格 | **待开始**（G1、G2） | gym 的结果本身永不排名。进入排行榜的路径不变：已登记并准入的方法、`nexttransformer.train`、`export_run` 和披露卡片 |
| 约束边界 | **部分完成**（G3） | 已有 API 封存，但静态检查不是沙箱：训练仍能读到官方数据，gym 的 L 运行只在最后评测 CORE，而不是在六个正式评测点 |

## G3 的评分运行时

一个固定的运行时，训练和评分在分开的容器里。普通贡献和竞技场 pull request 不需要容器。运行时及其工具尚未进入本仓库。

| 编号 | 状态 | 已交付 | 剩余工作 |
|---|---|---|---|
| P0 — 参考采集 | **部分完成** | 采集工具和一个 `dense_full` 参考 | 确认参考范围和身份：源码、软件、内核、输入和设置 |
| P1 — 运行时构建 | **部分完成** | 容器构建工具和一个带清单的已构建候选 | 选定一条可用的硬件和启动路径；它的清单和支持范围 |
| P2 — 直接评分 | **部分完成** | 启动器、预检、受限的检查点加载、结果校验器和比较工具 | 验证真实的 GPU 启动和隔离路径，精度、编译器和缓存设置，以及失败处理 |
| P3 — 数值一致性 | **部分完成** | `dense_full` 的最终检查点在参考硬件上、用户态容器中评分，BPB、CORE 和全部 22 个任务分数与训练结束时的评测逐位一致 | 其他模型、内核和硬件需要各自的证据；尚未证明容器级别的隔离 |
| P4 — 发布 | **待开始** | — | 第一条路径的不可变运行时身份、清单和支持范围；在另一台干净机器上通过测试 |
| P5 — Harbor | **部分完成；推迟** | 固定版本的生成器和控制器；CPU 传输验证 | 核心路径可用之后的可选 GPU 试验；开放竞技场不需要它 |
| P6 — gym 隔离 | **待集成** | 与 G3 是同一项 | 训练、更新和续训的验收，以及经过测试的模型、数据和评分边界 |

## 已批准的细化项

维护者于 2026-10-29 批准。它们细化上面的工作，不是额外的工作项。

| 编号 | 细化 | 状态 | 验收与范围 |
|---|---|---|---|
| AR-01 | A1，先于 A3 | **部分完成；已做有界验证** | 经过审阅的候选、真实分词器和数据、一次 S 运行、新进程续训、预算结算、跨会话恢复、可检查的归档和披露草稿（尚未完成）。这是有界验收，不是完整的 L0 运行 |
| AR-02 | G2 | **待开始** | 先比较初始化、数据、损失、优化器和恢复；再验证冻结候选的身份、189 次验证和六次 CORE 评测、累计核算和导出资格。优先复用正式训练器；任何新的排行榜规则都属于 Arena v2 |
| AR-03 | A2 | **前几个阶段已完成** | 选取有代表性的家族和阶段，预先登记相关性、扩展和更长前缀的判据；只根据这些证据扩展；绝不用小子集声称所有方法的排名 |
| AR-04 | G3 / P6 | **待开始** | 训练无法接触官方数据或改动评分；独立的验证者和不可变的模型交接；既测试被禁止的访问，也测试成功路径。普通 pull request 仍然不需要容器 |
| AR-05 | P1–P4 | **待开始** | 一条可用的硬件和启动路径、真实 GPU 执行、隔离和一个干净的使用方；写明不支持的路径；Harbor 和更多后端延后 |
| AR-06 | A4 | **部分完成** | 先开放普通的 pull request 赛道，不必等 G3 或 A3。仓库已经开源；剩下产物托管 |
| AR-07 | G4 | **待开始** | 披露实测的研究算力及其来源、失败和验证中的尝试、GPU 小时、墙钟时间和 LLM 使用，未知值为空；在有可比较的研究过程和排名规则之前，按研究者的展示只做描述 |

## 顺序

运行验收与贡献路径并行推进。AR-01 和第一条隔离路径（G3、P6）先于任何无人值守的 agent（A3）。A2 的证据决定后续研究算力投向哪里。G4 从披露开始。这里不意味着要做大范围的硬件或种子扫描。
