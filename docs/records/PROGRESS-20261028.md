## Reading the results

Every reference run below targets seed 42, 46,875 updates and 49.152B input tokens. A complete schedule has 189 validations and six full CORE-22 events. BPB is lower-is-better; CORE is higher-is-better on its 0–1 scale. **Final validation BPB means the independent final 20,971,520-token pass**, except in the explicitly labeled historical-native table. Periodic validation uses 41,943,040 tokens and is a different measurement.

The current theoretical anchor is **SSSL, 4.67239832544785 GFLOPs/input token**. The independently trained `dense_full` row is the quality baseline; these identities are separate. Hardware, rank count, parameters, speed and GPU-hours differ between runs. All scores are single-seed observations.

The QKNorm rows add the native per-head QK RMSNorm with gain 1.2 after reconstruction/RoPE to O03 `mla` and O03-N `mla_nope`, at their calibrated 26 layers / FFN 6144; pilot criteria were registered before the pilots.

Both H20 runs started from update 0, used four nodes / 32 H20 GPUs, microbatch 16 × accumulation 1, BF16, compilation, strict deterministic algorithms and flash SDPA, and completed in one segment. MLA-QKNorm finished at **2026-10-28 02:15:51 UTC+8**; MLA-NoPE-QKNorm at **01:57:27 UTC+8**. The bounded checks established bitwise resumes before launch. Warn-only cuDNN determinism had failed that requirement and was not used for the formal runs.

The read-only final audits verify the full event schedule, cumulative budget, final BPB consistency, provenance, canonical CORE task sets, centering and aggregate values, and the final checkpoint completion marker/file inventory. Tensor payloads were not loaded or rehashed. The runs had **zero logged loss jumps greater than 1.0 above the running minimum after update 1,000**, zero adjacent validation increases greater than 0.005, and maximum gradient norms after update 500 of **1.185 / 0.759**. These bounded diagnostics support the stability description; they do not compare every unlogged update.

MLA-QKNorm's final BPB/CORE is 0.673241/0.325330, versus 0.682963/0.276536 for MLA-NoPE-QKNorm. All Others rows disable Value Embeddings; O00 `mha_no_ve` is still missing, so a difference from Dense cannot isolate KV parameterization from VE policy and calibrated architecture. Latent-cache decoding is not implemented, and no measured decode savings are claimed.

Preregistered 512-update pilots and the H20 checks remain separately accounted; the latter used 151 GPU-hours by job duration. Training GPU-hours in the table exclude evaluation, pilots and checks, and are not total project resource usage.
