# v2: new architectures and remaining work

This is the **design and acceptance reference** for v2, registered on 2026-10-22 and consolidated on
2026-10-29. Current completion state, owners, evidence and remaining work are maintained only in
[PLAN.md](../../PLAN.md#evidence-and-remaining-limits). A definition or requirement here does not imply
that its implementation or formal experiment is complete.

The [protocol](../../PROTOCOL.md) fixes the shared scientific contract. [SOURCES.md](../methods/SOURCES.md)
records source versions and native adaptations; [CONFIGURATIONS.md](../methods/CONFIGURATIONS.md)
records selected structures and audited costs. This document preserves the cross-family design choices,
paired controls and acceptance requirements. The [hybrid reference](V2-linear-hybrids.md) retains the
more detailed source review and backend requirements; dated outcomes remain in
[EXPERIMENTS.md](../records/EXPERIMENTS.md).

## 1. Full-attention Dense comes first

| ID | Definition | Acceptance boundary |
|---|---|---|
| B00 `sssl` | Historical `dense` API/config: 24 blocks with the SSSL window layout | Preserve its identities, historical runs and frozen 4.67239832544785 GFLOPs/input-token cost anchor |
| B01 `dense_full` | Full causal MHA in every layer; 12 Q / 12 KV heads, head dimension 128; native shell and VE | Independent registration, calibration, validation and from-scratch training; quality-baseline acceptance is separate from implementation |

Start calibration at 24 layers / FFN 6144 and use only the
[registered grid and tie-break](../../PROTOCOL.md#training-compute-and-calibration). Do not infer unaudited
parameter counts or raise the budget. The selected dimensions and proof are linked from
[CONFIGURATIONS.md](../methods/CONFIGURATIONS.md#full-attention-dense-and-residual-rows) and the
[configuration](../../configs/baseline/dense_full.json).

- Serialize the all-full layout and test visibility in every layer and at every relevant length. A window
  helper that expresses all `L` does not establish the independent identity, admission, trace or result mapping.
- Require independent preflight cost evidence within 1%, including backward and optimizer work.
- Verify full-size BF16, a complete update, data flow and fresh-process resume.
- Apply the preregistered pilot policy, then a fresh 49.152B-token run with 189 validation and six complete
  CORE events. Historical owner-approved pilot exceptions remain recorded in the experiment log.
- Enable quality-baseline comparisons only after final cumulative acceptance within 2%; the accepted record
  and its evidence are tracked in [PLAN.md](../../PLAN.md#baseline-and-existing-families).

Historical looped rows retain their SSSL unfolded layouts. Full-layout looped controls isolate recurrence
from window policy; naming the full-attention baseline does not silently change existing algorithms.

## 3. Hybrids with registered source evidence

`N` is the calibrated physical block count. Layer positions below are **one-based**. No implicit “last layer is full” override may add an unregistered attention layer. Hybrid means a combination of mechanisms; it does not necessarily contain full attention.

| ID | Preregistered layout | Source / scope | Global attention? |
|---|---|---|---|
| H01 `deltanet_hybrid` | Even N; full causal MHA at layers **2 and N/2+1**; DeltaNet elsewhere | [DeltaNet §3.4](https://arxiv.org/html/2406.06484v1); native MHA adaptation of the global hybrid, not the separate local-MQA variant | Two layers |
| H02 `gdn_hybrid` | Repeat **GDN, GDN, GDN, full MHA**; N divisible by 4 | [Qwen3-Next](https://qwen.ai/blog?id=qwen3-next) 3:1 layout; retain this repo's GDN and native MHA, not the full gated-attention/MoE recipe | One quarter of layers |
| H03 `gdn_hybrid_swa` | Alternate **GDN, SWA**; window **2048 including current token**; even N | [GDN §3.3 H1](https://arxiv.org/html/2412.06464v1), [official configuration](https://github.com/NVlabs/GatedDeltaNet/tree/main/lit_gpt) | Local by design; effectively global at this 2K context |
| H04 `kda_hybrid` | Repeat **KDA, KDA, KDA, full MLA-NoPE**; N divisible by 4 | [Kimi Linear §4](https://arxiv.org/html/2510.26692v1), [official implementation](https://github.com/MoonshotAI/Kimi-Linear); do not substitute MHA for MLA | One quarter of layers, using MLA |
| H05 `qsa_hybrid` | Repeat **GDN, GDN, GDN, QSA**; N divisible by 4 | [QSA §2.1.1–2.1.2](https://arxiv.org/html/2608.30320v1); reuse local GDN/QSA adaptations, without GR, n-grams, MoE, MTP | No full layers in the sparse stage; teacher/burn-in accounted separately |
| H06 `moba_hybrid` | First **N−3** blocks MoBA, final **3** full MHA | [MoBA §3.2](https://arxiv.org/html/2502.13189v1); preserve the last-three rule and disclose the changed proportion after scaling from 32 layers | Final three layers |

Selected structures and costs are maintained in [CONFIGURATIONS.md](../methods/CONFIGURATIONS.md),
with source adaptations in [SOURCES.md](../methods/SOURCES.md) and current acceptance in
[PLAN.md](../../PLAN.md#hybrid-family-and-its-controls). H03's 2048-key window covers the entire 2K context,
so it measures a 1:1 GDN/full-attention hybrid. Do not reduce its window to 512 to manufacture sparsity;
a smaller-window experiment requires a separately named and approved adaptation. GDN H2 includes Mamba2;
omitting Mamba2 does not reproduce H2.

Do not add unsubstantiated hybrids: [GSA](https://arxiv.org/html/2409.07146v1) describes hybrid pretraining as future work; [GLA](https://arxiv.org/html/2312.06635v2) and [RetNet](https://arxiv.org/html/2307.08621v4) chunk algorithms do not themselves specify cross-layer full attention. NSA's branches and DSA/Seer's dense teachers are not evidence of such a layout. New evidence must include paper version, section, official configuration, and exact layout.

Implementation requirements:

- Add serializable per-layer mixer types, arguments, and execution traces. One global `method` cannot express these layouts. (H01–H06: `layer_mixers`, per-layer windows, trace fields.)
- Lock ratios and positions before calibration. Search N=16–32: multiples of four for 3:1, even N for alternation/two-global rows; expand the final-three rule for MoBA.
- Full MHA follows B01's projection/norm/RoPE rules. H04 reuses real MLA-NoPE, disables VE, and has independent `kda_no_ve` / `mla_nope` controls and the shared `mha_no_ve` control. Pilot/formal acceptance is separate.
- During H05's first 512 updates, only QSA positions use dense burn-in and indexer teacher; GDN remains GDN. Sum auxiliary terms over QSA positions with the pure row's policy. This is not the paper's mature-model 256K CPT recipe.
- Audit every layer's projections, edges, state, VE, auxiliaries, forward/backward, and optimizer, then weight training stages. Do not average pure-method proofs by layer ratio.
- Validate causality, state reset, loss ownership, full-size backward, complete updates, and resume. Report global-layer positions, effective windows, mixer parameter/FLOPs shares, and state/KV memory.

## 4. Residual: a separate family

First compare residual organization on a nonrecurrent, all-full-MHA shell. Do not combine multiple new architecture changes in the first experiment.

The native shell has `resid_lambdas`, `x0_lambdas`, and backout. Register **`residual_standard`** with ordinary `h + F(norm(h))`, disabling those learned residual/x0 and backout paths. HC, mHC, and AttnRes replace the same paths. Retain smear, VE, FFN activation, embeddings, and training protocol. B01 Dense keeps its native shell unchanged. Report the paired-control difference and the overall Dense difference separately.

| ID | Registered mechanism | Acceptance | Original owner |
|---|---|---|---|
| R00 `residual_standard` | Single-stream standard residual control, full MHA | Match explicit reference output/gradient; no leftover x0/backout path | @selen |
| R01 `hc` | [Hyper-Connections](https://arxiv.org/html/2409.19606v3), dynamic HC, **4 residual streams**; attention and FFN each wrapped; branch width remains 1536 | Original initialization and read/write mixing; stream shape and gradients; branch is not widened to 4d | @selen |
| R02 `mhc` | [mHC](https://arxiv.org/html/2512.24880v2), 4 streams; pre/post/res mappings; **20 Sinkhorn-Knopp iterations**, gate-scale initialization **0.01** | Nonnegativity, row/column errors, composed maps, gradients and residual norms; finite iterations are not exact double stochasticity | @selen |
| R03 `attnres` | [Attention Residuals](https://arxiv.org/pdf/2603.15031), [official implementation](https://github.com/MoonshotAI/Attention-Residuals): RMSNorm keys, learned pseudo-query, depth softmax; block-local sums and cross-block selection, approximately **8 groups** | Correct embedding/completed-block/current-partial-sum boundaries; separate attention/FFN queries; no double residual or future-token leakage | @selen |

Selected dimensions and group boundaries are maintained in
[CONFIGURATIONS.md](../methods/CONFIGURATIONS.md#full-attention-dense-and-residual-rows).
The calibrated mHC FFN is 6016 rather than R00's 6144; report that difference in the paired comparison.
The rejected FFN/depth candidates and costs remain in the configuration reference and proofs.
The mHC paper does not specify static-bias initialization: preserve HC's Eq. 14 values before the
constraints, as documented in the [source adaptations](../methods/SOURCES.md#full-attention-dense-and-residual-family).

HC is the mechanism control for mHC. Published evidence comes from different scales and backbones, including MoE; it is not a prediction of this project's gains.

- Count stream expansion/reduction, dynamic projections, norms, mixing, all Sinkhorn iterations, real backward, and optimizer. Four residual streams are not four full FFNs, but do add activation/memory costs.
- Lock author-reference initialization and aggregation; explicitly group special parameters, using the registered auxiliary AdamW policy unless a necessary exception is documented.
- Count AttnRes depth in **attention and FFN sublayers**, not just blocks. Serialize eight group boundaries after calibration, approximately balancing whole transformer blocks; final readout includes embedding and all completed groups. Disclose this local adaptation.
- Reserve `attnres_full` for an optional separate full-depth-source ablation; “Full” here does not mean token-level full attention.
- Independently calibrate every row from 24 layers / FFN 6144; FP64 operator oracles, R00 pairing, full-size BF16, complete-update/resume, and memory checks (bounded; record 028).
- Apply equal-budget pilots if used, verify long-run BF16 stability, and meet formal-run acceptance. Current run and resume evidence is maintained in [PLAN.md](../../PLAN.md#residual-family), including recorded owner-approved pilot exceptions.

## 5. Others: MQA, GQA, and MLA

These rows use **global causal attention in every layer**, width 1536, 12 query heads, context 2048. Fewer KV heads do not make a model sparse.

VE dimensions depend on KV heads, and MLA's latent representation has no identical VE interface. Therefore all Others rows **disable VE**, with a separately calibrated full-MHA-noVE control. B01 keeps VE. MLA-NoPE and its dependent KDA-hybrid also disable VE; add `kda_no_ve` so the effect is interpretable.

| ID | Preregistered starting structure | Source / adaptation |
|---|---|---|
| O00 `mha_no_ve` | Full MHA, **12 Q / 12 KV**, dimension 128, no VE | Same B01 shell except VE |
| O01 `mqa` | **12 Q / 1 KV**, Q/K/V dimension 128 | [Multi-Query Attention](https://arxiv.org/abs/1911.02150), shared KV projections |
| O02 `gqa` | **12 Q / 3 KV**, four query heads per group, dimension 128 | [Grouped-Query Attention](https://arxiv.org/abs/2305.13245); three KV heads is this project's registered choice |
| O03 `mla` | Joint KV latent rank **256**, Q rank **768**, 12 heads, QK content/RoPE dimensions **64/64**, V dimension **128** | [DeepSeek-V2 MLA](https://arxiv.org/html/2405.04434v5); joint compression, up-projections, decoupled RoPE; dimensions adapted to width 1536 |
| O03-N `mla_nope` | Same ranks/heads/V; QK content **128**, RoPE **0** | Independent full-MLA-NoPE control for H04 |

Frozen-branch evidence and mainline implementation admission are separate. Preserve the original run
sources and results, and apply these requirements when integrating each definition into the public model
interface. [PLAN.md](../../PLAN.md#others-completed-results-versus-mainline-support) tracks both states;
the [dated report](../records/PROGRESS-20261028.md#others-completed-runs) remains a historical snapshot.

All sizes above are starting points, not calibrated parameter-count claims. Freeze KV grouping, ranks, and QK/V dimensions before depth/FFN calibration. Train from scratch; no free MHA-to-GQA uptraining, and no added MoE.

- Separate Q and KV shape fields in configuration/checkpoint code. Match shared-K normalization, grouping, and summed gradients to an explicitly expanded MHA oracle.
- QK/AV still serve **12 query heads**: do not divide all attention FLOPs by the KV-head ratio. Count KV projections, shared-gradient reductions, norms, RoPE, output, and backward separately.
- Implement actual MLA compression, latent norms, up-projections, content/rotary branches, scaling, and backward. One low-rank linear layer is insufficient.
- Verify explicit reconstructed KV first, then the supported projection-absorption/latent-cache equivalences. Report decode/KV-cache savings only after implementing and measuring those interfaces.
- Report overall B01 differences and paired noVE-control differences; separate parameter changes due to KV projections, VE policy, latent ranks, and calibrated depth/FFN.

## 6. Integration and release checklist

Model work belongs in `nexttransformer/models/`; protocol, configuration, cost audit, and calibration in `nexttransformer/protocol/`; the trainer is `nexttransformer.train`. Residual mechanisms belong in `residual.py`; shared MLA components belong in `others.py`. Track each method's mainline support in [PLAN.md](../../PLAN.md#others-completed-results-versus-mainline-support). Preserve the legacy `dense` API as SSSL rather than performing a global semantic rename.

Every row needs: source/version and adaptation card; scientific config and layer layout; independent proof; numerical/causality/backend checks; actual global-update and resume checks; pilot accounting; and a complete final run with evaluation and cumulative acceptance. New source changes invalidate old cost evidence. Existing merge checks do not cover unimplemented v2 architectures.

The observatory must expose the registered families and hybrid tags, exact baseline/control relationships, source/config/protocol fingerprints, and missing-value behavior. Preserve historical scores, old formulas, failures, and original run IDs. The [protocol](../../PROTOCOL.md#result-admission-and-release) governs publication status.
